# Bundled asset provenance and redistribution audit

Scope: `exts/ur5e-dt/assets/` on `main` at `d8954ad`, 110.0 MB in 176 files.
Audit date: 2026-11-01. This is an engineering provenance audit, not legal advice.

The repository is being prepared for a **fresh public repository**. The rule for that copy is:
ship only assets whose licence permits redistribution; make everything else available on demand
from its official source, or use the copy already installed on the operator's machine.

## Evidence by group

### NVIDIA robot and sensor — not redistributable

- Commit `3d97d82` (*"Bundle all assets locally, remove Nucleus/external path dependencies"*,
  2026-03-02) says it collected the robot, gripper and sensor from Nucleus with
  `omni.kit.usd.collect.Collector`. The pre-bundle code in the same commit used
  `omniverse://localhost/Library/ur5e.usd` and
  `omniverse://localhost/NVIDIA/Assets/Isaac/5.0/Isaac/Sensors/Intel/RealSense/rsd455.usd`.
- `robot/SubUSDs/ur5e_base.usd` is byte-identical (SHA-256
  `12347912499e3ead2c0fa1ba782dee8b87fa9255397baeba94d99480b01e3ea8`) to
  `Assets/Isaac/5.0/Isaac/Robots/UniversalRobots/ur5e/configuration/ur5e_base.usd` on NVIDIA's
  public asset root. `ur5e_sensor.usd` is also identical; `ur5e_physics.usd` differs only by a
  `./` in its `ur5e_base.usd` sublayer path.
- The bundled `robot/ur5e.usd` is that NVIDIA file plus local edits: sublayer paths rewritten to
  `./SubUSDs/`, the `configuration/ur5e_robot_schema.usd` sublayer dropped, a `tool0` Xform added
  under `wrist_3_link/flange`, and viewport render prims added by a stage save. It is a derivative,
  not a new model.
- `sensors/rsd455.usd` and `sensors/SubUSDs/` are the Isaac 5.0 RealSense D455 model with NVIDIA
  `Aluminum_Anodized`, `Aluminum_Cast` and `Plastic_ABS` materials and textures collected beside it.
- NVIDIA's licence FAQ states that the additional NVIDIA-licensed components — "Omniverse Kit SDK,
  assets, etc." — "may not be modified or redistributed except as expressly permitted by their
  license terms":
  <https://docs.isaacsim.omniverse.nvidia.com/6.2.0/common/license-faq.html>
- The files are publicly fetchable from NVIDIA's asset root without an account, e.g.
  <https://omniverse-content-production.s3-us-west-2.amazonaws.com/Assets/Isaac/5.1/Isaac/Robots/UniversalRobots/ur5e/ur5e.usd>
  and the matching `configuration/` and `Isaac/Sensors/Intel/RealSense/` paths. Fetching them into
  a local cache is not redistribution.

### Vention workstation — not redistributable

- Commit `71c2228` says the bench was collected with `omni.kit.usd.collect` from the source scene
  and its `Rubber_Smooth` MDL and textures were rewritten to local relative paths.
- The stage metadata names `creator = Omniverse Hoops Converter 2.0.0` and the only top-level
  assembly is `VentionAssembly_393251_v88_0`, which is a Vention MachineBuilder export.
- Vention's Terms of Use reserve all rights in downloads and prohibit reproducing, modifying,
  creating derivative works from, distributing or commercially exploiting the service's content
  except as expressly permitted: <https://vention.io/terms-of-use>.
- `workstation/NVIDIA/Materials/Base/Plastics/Rubber_Smooth` is an NVIDIA material-library asset
  and is covered by the NVIDIA terms above.
- If the bench design is the owner's own Vention document, that does not grant a right to publish
  the CAD export; Vention's terms still apply. Treat the bench as an operator-supplied asset.

### OnRobot RG2 and Quick-Changer — Apache-2.0

- `adapter_ref/package.xml` declares `<license>Apache License 2.0</license>` and points at
  <https://github.com/husarion/ur_onrobot_rg2_ros>.
- Every file in `adapter_ref/meshes/` (`finger`, `hand`, `quick_changer`, `moment_arm`,
  `truss_arm`, both `.stl` and `.dae`) is byte-identical to the corresponding file in
  `onrobot_rg2_description/meshes/` of that repository. The three URDF/xacro files and
  `package.xml` are also byte-identical. The repository root `LICENSE` is Apache-2.0.
- `gripper/husarion_rg2/` and `gripper/QuickChanger.usd` are USD conversions of those files,
  produced by `tools/convert_husarion_rg2_urdf.py` and `tools/rewire_husarion_rg2_usd.py`.
  Apache-2.0 permits redistribution of modified versions provided the licence and notices are
  retained; mark the converted files as changed.
- `gripper/husarion_rg2/husarion_rg2_fixed.usd` is the old rollback build. It is not referenced
  by the current code, it adds 2.5 MB, and its `doc` metadata contains a foreign home path. Remove
  it rather than carrying a third copy of the gripper.

### FMB objects — CC BY 4.0

- Commit `3d97d82` says it copied FMB objects into `assets/objects/fmb1|fmb2|fmb3`, and the
  assembly names (`base1`, `u_brown`, `line_green`, `inverted_u_yellow`, ...) match the FMB object
  set.
- The FMB project publishes the object and board CAD under "All data is provided under the
  Creative Commons Attribution 4.0 International License":
  <https://functional-manipulation-benchmark.github.io/files/index.html> (also stated on the
  dataset page).
- Required attribution: *FMB: A Functional Manipulation Benchmark for Generalizable Robotic
  Learning*, Luo et al., UC Berkeley, <https://functional-manipulation-benchmark.github.io/>,
  CC BY 4.0. State that the CAD was converted to USD, materials and physics were authored, and
  some objects were renamed or rescaled.
- The five `fmb1` `.usda` files embed a `doc = "Generated from Composed Stage of root layer ..."`
  string containing another person's home directory and an `aruco-grasp-annotator` project path.
  Scrub it in the same change; do not publish it.

### Jenga objects — replace the Poliigon textures

- Commit `f41e9e4` says the six `fmb4` USDs were authored by the twin's CAD-to-USD tooling and
  passed the grasp gate. The geometry is the project's own work.
- The material is Poliigon `WoodVeneerOak_7760` (seven JPG/PNG files and an `.mtlx`,
  8.8 MB). Poliigon's licence FAQ answers "Can I embed Poliigon textures or models in my model or
  scene that I sell or redistribute?" with "Unfortunately no", and its terms prohibit providing
  the assets to third parties in a redistributed form:
  <https://help.poliigon.com/en/articles/8749749-asset-use-licensing>.
- Keep the block geometry and replace the oak with a generated or CC0 material. A flat `OmniPBR`
  colour is enough at this scale and removes the 8.8 MB.

### Generated and authored files

- `objects/aruco/` contains marker images generated from the standard OpenCV 4x4 and 5x5
  dictionaries plus pose JSON produced by the twin's tooling. The dictionary patterns are not
  copyrightable and the JSON is project work.
- `fmb_assembly*.json`, `objects/materials/Plastic.mdl` and the `_physics` overlays are project
  authoring, covered by the repository licence. `Plastic.mdl` is a small parameter block that
  imports NVIDIA's `OmniPBR` module; it does not contain NVIDIA geometry or textures.
- `gripper/RG2.usd` is the superseded Robotiq-relabelled gripper. Its default prim is
  `/khi_rs080n` (a Kawasaki RS080N) with OnRobot RG2 links. Commit `0d29f84` replaced it with the
  Husarion RG2; no current code path references it. The Kawasaki geometry is third-party and its
  provenance is not documented, so remove it.

## Fetch-on-demand design

The twin runs inside Isaac Sim, so the operator already has a licensed copy of every NVIDIA asset.
`exts/ur5e-dt/ur5e_dt/asset_cache.py` resolves an asset in this order:

1. **Bundled** — `exts/ur5e-dt/assets/<path>`, for the redistributable files.
2. **Operator cache** — `$UR5E_DT_ASSET_CACHE` (default `~/.cache/ur5e-dt/assets`), populated by
   `scripts/fetch_ur5e_assets.py`.
3. **Pinned NVIDIA asset root** — the HTTPS S3 URL recorded in
   `exts/ur5e-dt/assets-manifest.json` for `robot/ur5e.usd` and `sensors/rsd455.usd`. Isaac Sim's
   asset resolver accepts the URL directly, so a run with network needs no download step.

The manifest pins the Isaac 5.1 generation because the twin was authored against those files; the
old bundle was the 5.0 generation and already ran on the supported 6.x releases. The fetcher
verifies the recorded SHA-256 and byte size, so a cached copy is reproducible. The resolver also
checks a cached file against the manifest before use; a mismatch raises `AssetCorrupt` with the
`--force` command. Set `UR5E_DT_OFFLINE=1` for an air-gapped run: a missing cache entry then fails
with `AssetMissing` and the fetch command instead of returning an unreachable URL. `load_ur5e`
creates the missing `tool0` Xform at load time.

The workstation has no public source. `load_workstation` accepts a user-supplied `vention.usd` in
the cache and otherwise builds a simple placeholder bench with the same top-at-z=0 contract. The
bench is visual context only; the robot and object tools do not depend on it.

Poliigon cannot be fetched automatically because it needs an account. Replacing the oak material
removes the dependency entirely.
